# 2026.330.1804 — feat(web-layer): compose the fixture on Arch/CachyOS, not Fedora only

## Summary

The fixture could be built on Fedora only: its `distro:` map carried a `fedora` section alone, so an
Arch or CachyOS image composing it got no nginx, curl, iproute or procps-ng and the service could
not start. That stayed invisible while every consumer happened to be a Fedora box — and it became
the blocker the moment the org's pod-to-pod CDP probe needed a web SUBJECT on CachyOS
(opencharly/distro-fedora#140, whose Fedora driver was retired with #138 and whose replacement is
CachyOS+KDE).

The `arch` section carries the same set under the Arch names: `iproute2` (Fedora's `iproute`),
`procps-ng` (the same name), `curl` and `nginx`. Nothing else changes, and it does not need to:

- the `nginx.conf` the candy writes is self-contained — its own `pid`, `error_log` and every
  `*_temp_path` under `/tmp` — so it needs none of a distro's default layout and no `user` directive
  (nginx's master runs as root and its workers as the compiled default on both);
- the service's absolute `/usr/sbin/nginx` resolves on Arch too, because Arch's usr-merge makes
  `/usr/sbin` a symlink to `/usr/bin` — measured, not assumed:

  ```
  $ podman run --rm localhost/pod-cdi:<tag> sh -c 'ls -ld /usr/sbin'
  lrwxrwxrwx 1 root root 3 Oct 12  2025 /usr/sbin -> bin
  ```

The description now states the cross-distro contract and why it holds, so the next consumer does not
have to re-derive it.

### Spike

Two candidate shapes for "make the fixture cross-distro", and one measurement that removed a third:

```
# (a) a distro.arch section beside distro.fedora (CHOSEN) — the subject image builds and serves:
  PASS  check the fixture page the subject serves carries the marker …  [kde-web-subject-fixture]  ok
  PASS  check the web SUBJECT serves its fixture marker on its own published port  [cross-web-subject-up]  status=200
  (run 2026.330.1704, exit 0)

# (b) a second, arch-only fixture candy — rejected by rule, not by a run: two fixtures for one
#     marker would be the duplication R2 forbids, and the next distro would need a third.

# (c) change the service's exec path for Arch — measured UNNECESSARY before writing it:
$ podman run --rm localhost/pod-cdi:<tag> sh -c 'ls -ld /usr/sbin'
lrwxrwxrwx 1 root root 3 Oct 12  2025 /usr/sbin -> bin
```

Winner: (a). It keeps ONE fixture and ONE marker for every distro.
